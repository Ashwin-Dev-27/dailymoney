# Onboarding and Tutorial Specification

> **Internal engineering document.** This is not a public policy. It describes
> the onboarding behaviour implemented in DailyMoney 1.3.1+8 and the checks still
> required before release.

- **Version:** 1.1
- **Last updated:** 30 October 2026
- **App version described:** 1.3.1+8 (`com.dailymoney.app`)
- **Sources:** `lib/screens/welcome_screen.dart`,
  `lib/widgets/tutorial_overlay.dart`, `lib/app.dart`,
  `lib/providers/settings_provider.dart`

## 1. Goals

1. Explain the app before asking the user to use it.
2. Collect a genuine, explicit policy acceptance.
3. Leave every optional permission off.
4. Offer a short tour that uses the real controls.
5. Never create a financial record without a deliberate user action.
6. Let the user skip the tour, replay it later, and reset onboarding without
   losing data.
7. Preserve existing installs across the upgrade.

## 2. Entry points

| Entry point | Behaviour |
|---|---|
| First launch (no prior settings) | `WelcomeGate` shows `WelcomeScreen` because `welcomeSeen` is false. |
| Existing install upgraded to 1.3.1 | `welcomeSeen` defaults to the persisted `seeded` flag. Installs that were seeded by an older build keep `seeded = true`, so the welcome screen is not shown as if the app had been reset. |
| Full data wipe | `resetToDefaults()` sets `welcomeSeen = false` and keeps `seeded = true`, so the welcome screen returns and demo data is not re-injected. |
| Settings > Help & support > Replay guided tour | `replayTutorial()` starts the tour at step 0 without touching records. |
| Help centre > Replay guided tour | The Help Centre pops the pages above the shell and calls `replayTutorial()`, so the tour runs over the real app. |
| Settings > Help & support > Show welcome and tour again | `resetTutorialProgress()` clears onboarding state and shows the welcome screen. Records and legal acceptance are preserved. |

## 3. Welcome screen

### Layout

- Scrollable, safe-area aware, width capped at 520 dp.
- App icon, "Welcome to DailyMoney!", a one-line promise and three feature
  cards: safe-to-spend allowance, planning before money moves, and local-only
  storage.
- Two checkboxes, both unchecked by default:
  1. **Start with sample data** - only shown when the ledger is empty. Adds
     approximately 85 example transactions, a few bills and two goals.
  2. **I have read and agree to the Terms of Service and Privacy Policy.**
- Links open the full Privacy Policy, Terms of Service and Financial
  Disclaimer.
- Primary button: **Take a quick tour**.
- Secondary button: **Explore myself**.
- Both buttons are disabled until the legal checkbox is checked.
- Footer explains that the tour is optional, that optional permissions are
  requested only when the related feature is enabled, and that acceptance is
  recorded with the policy version and time.

### What happens on continue

1. `acceptPolicies()` stores `legalAcceptedVersion = kLegalVersion` and
   `legalAcceptedAt` (ISO-8601 timestamp).
2. If sample data was checked **and** the ledger is empty, the demo generator is
   applied. The flag is off by default. Sample data can be deleted later in
   **Settings > Data management**.
3. `markSeeded()` records that onboarding has run.
4. If the tour was chosen, `startTutorial()` sets `welcomeSeen = true`,
   `tutorialInProgress = true`, `tutorialStep = 0` and clears the skipped flag.
5. Otherwise `dismissWelcome()` sets `welcomeSeen = true`.
6. No permission is requested and no notification is scheduled by this flow.

### Safety properties

- Sample data is opt-in and never generated by `main.dart`.
- The legal checkbox has no default and no "accept all" shortcut.
- A version change is not silently accepted. The Legal & privacy hub shows the
  current version and an acceptance form when the stored version differs.

## 4. Guided tour

### Structure

- Ten steps, defined by `tutorialStepsFor(anchors)`.
- The overlay covers the whole shell, including the bottom navigation bar and
  the floating action button.
- A spotlight cut-out and a pointer highlight the real control.
- The card shows the step number, progress bar, title, body, optional action,
  Skip, Back and Next/Finish.
- A completion card replaces the last step after Finish.
- The tour changes tabs automatically and scrolls the target into view.
- Tapping outside the card does not advance; the user must use the controls.

### Steps

| Step | Title | Tab | Target | Behaviour and safety |
|---|---|---|---|---|
| 1 | Your money at a glance | Home | Balance/overview card | Explains confirmed balance and that it changes only when a transaction is recorded. |
| 2 | Today's spending money | Home | Daily allowance card | Explains the monthly budget split, bills and protected money. |
| 3 | Record an expense | Home | Floating add button | Offers **Open the entry sheet**, which opens the real sheet. Nothing is saved until the user reviews and taps Add. Closing the sheet changes nothing. |
| 4 | See where money goes | Insights | Category breakdown | Explains the last six months. If there is no expense data, shows a fallback message instead of an empty spotlight. |
| 5 | Set the monthly budget | Settings | Budget tile | Explains the daily allowance input. Opening Settings does not change the budget. |
| 6 | Try a future scenario | Settings | What-if tile | Explains that results are estimates. |
| 7 | Insights and alerts | Insights | Insights area | Explains patterns and optional budget alerts. Shows a fallback when there is no data. |
| 8 | Nightly summary | Settings | Nightly summary switch | Explains that Android notification permission is requested only when a notification feature is enabled. The switch is not toggled by the tour. |
| 9 | Privacy and permissions | Settings | Permissions & data tile | Explains storage encryption, permissions and export. |
| 10 | Your data controls | Settings | Data management section card | Explains deleting transactions and the full reset under Help & support > Legal & privacy > Data controls. |

### Persistence

`SettingsProvider` stores:

- `welcomeSeen`
- `tutorialCompleted`
- `tutorialInProgress`
- `tutorialSkipped`
- `tutorialStep` (clamped to 0-999; completion is stored as 999)
- `tutorialCompletedAt`

Transitions:

- `startTutorial()`: step 0, in progress, not skipped.
- `setTutorialStep(n)`: updates the step, keeps the tour in progress.
- `markTutorialCompleted()`: completed, timestamp, step 999, still in progress
  until the completion card is closed.
- `finishTutorial()`: in progress false, overlay closes.
- `skipTutorial()`: in progress false, skipped true, step reset to 0.
- `resetTutorialProgress()`: clears tutorial and welcome state only.
- Full wipe: clears all onboarding fields.

### Accessibility and reduced motion

- The overlay is a `Semantics` live region with a step label.
- `BlockSemantics` hides the shell behind the tour from the semantics tree.
- ArrowRight/ArrowLeft move between steps; Escape skips.
- `MediaQuery.disableAnimations` removes the pulse and pointer bob and uses a
  120 ms transition.
- The card is scrollable and capped at 62% of screen height.
- Every step has text; no step relies on the spotlight alone.
- Missing targets show the step's fallback text when one is defined.

### Data-safety guarantees

- The tour never calls a provider that writes a transaction, bill, goal,
  expected-income entry or shared expense.
- The tour never enables a notification or payment-detection feature.
- The tour never accepts a policy or records consent.
- Step 3 opens the real entry sheet, but saving still requires the user to fill
  the form and tap Add. The widget test asserts that the transaction count is
  unchanged after skipping the tour.
- Replaying or resetting the tour does not modify records.

## 5. Failure and edge cases

| Case | Behaviour |
|---|---|
| Target cannot be found (missing data or hidden section) | The card shows the step body or its fallback, centred at the bottom. The tour continues. |
| User leaves the app mid-tour | `tutorialInProgress` and `tutorialStep` persist; the tour resumes on return. |
| User skips | Tour closes and is marked skipped; replay remains available. |
| User completes | Completion card appears; Finish closes the overlay. |
| Fresh install with empty ledger | Tour steps 4 and 7 use fallback text. |
| Existing install | Welcome gate is skipped; the tour is not started automatically. |
| Full wipe | Welcome gate returns; no demo data is injected. |
| Reduced motion | Animations are minimised as described above. |

## 6. Test evidence

`test/onboarding_legal_test.dart` contains eight tests:

1. First run requires an explicit policy acceptance, both checkboxes start
   unchecked, and "Explore myself" records the acceptance.
2. Sample data is opt-in and generated only when requested.
3. The tour is skippable and does not create records.
4. The completion card returns to the app.
5. Policy acceptance and tour progress survive a reload.
6. Consent is purpose-specific and timestamped.
7. An existing install is treated as welcome-seen on upgrade.
8. A full reset clears onboarding and legal state while keeping `seeded`.

`test/narrow_layout_test.dart` and `test/reports_narrow_test.dart` cover the
phone-width layout. The ten-step tour was also run end-to-end on the Redmi
(`the Redmi test device`) on 30 October 2026: it was replayed from the Help Centre,
advanced through steps 1-10, and completed back into Settings with the ledger
unchanged. The cards for steps 7, 8 and 10 were positioned above or below their
targets and did not cover the highlighted control. TalkBack traversal, 200%
system text size and reduced motion are still device-pending.
